# Worked example — Pool Scout

An OpenAPI document, a hand-authored overlay, and the dictionary the generator
produces from the two. [`crypto-data.dictionary.json`](../crypto-data.dictionary.json)
next door is written by hand to show the format at its best; this one shows what
the format looks like when it meets a document nobody wrote for it.

Pool Scout is fictional. It is shaped like the API a liquidity-pool analytics
vendor actually ships — eight `GET` operations, one tag, placeholder response
descriptions, an API key on everything except the health check — because that
shape is the common case, and a generator that only shines on a perfect document
is not worth much.

```
openapi.json                 the upstream document, as a vendor would publish it
overlay.json                 the human knowledge, hand-authored (spec 15.2)
pool-scout.dictionary.json   generate(openapi) + overlay, regenerated by npm run example
```

## Rebuilding

```bash
npm run example
```

The arguments are in [`scripts/build-example.ts`](../../../scripts/build-example.ts)
rather than in this file, because `test/example.test.ts` regenerates with
exactly that argv and asserts the checked-in document comes back byte for byte.
A command in prose drifts; a command in a test does not.

Four of those arguments are worth explaining.

* `--strip-prefix api --strip-prefix public` — both are routing. Neither tells
  an agent anything, and both would otherwise land in every single name.
  `pools` is kept: it is the resource, and `get_pools_liquidity` reads better
  than `get_liquidity` once a second resource shows up.
* `--base-url https://api.poolscout.example` — the document declares
  `servers: [{ url: "http://localhost:4020" }]`, which is true for the service's
  own test harness and useless to a caller. A dictionary carries the URL the
  agent should actually call, so the base URL is supplied at generation time.
* `--source-url` and `--overlay-url` — recorded in `sources[]` as where a reader
  can fetch each input, not as paths on the machine that ran the build.
* `--generated-at 2026-09-16T00:00:00.000Z` — pinned so the output is a function
  of its inputs alone. Without it the example could not be a fixture.

## What the document gives, and what it does not

Eight operations, all `GET`, all under one tag. That is the honest starting
point, and it is worth being specific about what a generator can and cannot get
from it:

| | |
|---|---|
| `operationId` | **absent on all eight.** Names are derived from the method and the path, which is why the generator's naming rule (spec 15.1) is not a nicety |
| tags | **one**, `pools`, so the index is one category until the overlay adds a second |
| `summary` | present and good, but written as prose — the longest is 79 characters, right at the edge of what a `title` gets, so several read as sentences rather than labels until the overlay retitles them |
| 200 description | `"Default Response"` on all eight — a placeholder. `returns` is read off the **response schema** instead, which is the single largest quality difference between a generated entry and a useless one |
| response schemas | complete and richly described; this is where most of the real information in the generated half comes from |
| `securitySchemes` | one `apiKey` in the `x-scout-key` header, required by seven operations and not by `/health`. It becomes `defaults.auth` with the placement and a `{{POOL_SCOUT_API_KEY}}` variable, declared secret and described from the scheme; `get_pools_health` carries `auth: { kind: "none" }` so an executor sends nothing there |

## What the overlay adds

Everything in the second column of that table is machine-derivable. The overlay
carries what is not:

* **The words a person uses.** `rug`, `lp locked`, `who is buying`, `main pool`,
  `what would i earn` — none of these appear anywhere in the upstream document,
  and they are how the questions are actually phrased. `test/example.test.ts`
  asserts four of those questions land on the right tool.
* **Titles a human would write.** `Find a pool`, `Liquidity and lock status`,
  `Yield for providers` — short enough to scan a result list.
* **Relations the document cannot imply.** That `get_pools_liquidity` and
  `get_pools_providers` are the two halves of a rug check; that `get_pools` is
  the broader form of `get_pools_liquidity`; that `get_pools_search` is what
  *enables* everything else, because every other tool wants a pool address it
  does not have yet. The generator seeds `pairs_with` from shared inputs, which
  is true but weak — every tool here takes the same two inputs. An authored
  relation to the same target replaces the seeded one.
* **A second category.** `get_pools_health` is a liveness probe, not pool
  analysis; the overlay adds `pools/status` and moves it there. The index
  listings are derived, so the parent category stops advertising it
  automatically.
* **Worked examples** — a search for `SOL`, and a deep, long-lived pool, so the
  first call an agent makes returns a clean result rather than an error.
* **One catalog-wide edit.** The `"*"` entry patch removes `pools` and `pool`
  from every entry's keywords: they are on all eight, so they discriminate
  nothing. This is eight entries today and the same one edit at five hundred,
  which is the property the wildcard exists for.

## The three warnings it ships with

```
warning: entries[].keywords: keyword "chain" appears on 7/8 entries; it no longer discriminates
warning: entries[].keywords: keyword "fee" appears on 3/8 entries; it no longer discriminates
warning: entries[].keywords: keyword "liquidity" appears on 4/8 entries; it no longer discriminates
```

These are correct and deliberately not silenced. `chain` genuinely does not
discriminate between these tools — but it is the one word an agent holding a
chain name is sure to have, and a search for it should land somewhere in this
dictionary rather than nowhere. `liquidity` and `fee` are the subject matter;
a one-word question about either should reach the liquidity or volume tool, not
the index. Ranking already discounts a term that common, so the cost is small and the
floor is worth keeping. The `"*"` patch above shows how to drop them in one
line if a catalog decides otherwise.
